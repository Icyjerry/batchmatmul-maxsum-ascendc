# 算子定义与约束

## 数学定义

逻辑输入 `X1[B,M,K]`、`X2[B,K,N]`：

```text
C[b,m,n] = sum_k X1[b,m,k] * X2[b,k,n]
R[b,m]   = max_n C[b,m,n]
y[b]     = sum_m R[b,m]
```

第 b 组只与第 b 组配对，不 broadcast。输入相同 dtype，FP16 或 BF16；输出 FP32 `[B]`。Golden 对实际存储值使用 FP64 计算，最后转换 FP32。

| 属性 | false 的存储 shape | true 的存储 shape |
|---|---|---|
| transposeX1 | `[B,M,K]` | `[B,K,M]` |
| transposeX2 | `[B,K,N]` | `[B,N,K]` |

属性仅声明存储布局；不能改变逻辑数学结果。

- 输入连续 ND，无空 tensor、NaN、Inf、mask、padding 或有效长度输入；不做 L2 归一化。
- 允许负值；行最大值以 `-inf` 或第一个有效元素初始化。
- K 点积和两级归约使用 FP32 或等效精度；完成 K 累加以后才可做 Max。
- 非对齐 M/N 尾块必须只包含有效 token，不能让补零替代负数最大值。
- 不修改输入，不越界写 y；多次执行结果应一致。
- 15 个正式测试点全部过精度才计分。每点分数 `100 / (1 + log_1.5(t/T))`，最终取均值；没有实测 t/T 时不估计得分。

## 尚需正式材料确认

用户粘贴的题面部分维度上限、shape、元素数限制因公式丢失而缺失。当前队友代码 Validate 强制：

- `1 <= B <= 64`，`1 <= M,N <= 8192`。
- `32 <= K <= 8192`，K 为 8 的倍数。
- `B*M*K <= 2^26` 且 `B*N*K <= 2^26`。

以上是**当前实现条件**，不可冒充已完整核对的正式赛规。题面讲解示例 K=2，仓库某 Python 示例 K=4，当前 kernel 不接受这些小 K；正式测试范围需要真实赛题/评测配置确认，不应改 golden 掩盖差异。

题面同时列出 FP32 `1e-4`、FP16/BF16 `1e-3` 精度，当前输出是 FP32。使用正式评测器并同时记录绝对/相对误差，不自行放宽判断条件。

## 指令演变与 workspace

早期用户开发附件明确禁止额外 GM workspace；队友版本在 run_kernel 内用 aclrtMalloc 缓存系统 workspace、partial 和环形缓冲。已经向用户说明这个冲突，随后用户明确要求“在这份上验证你的想法、探索和开源论文及项目中的经验”，据此当前开发沿用该架构。

这代表当前开发基础选择，不代表已查明正式竞赛是否允许这种分配。后续 Agent 应保留这一背景，不重新卡在接口没有 workspace 参数，也不宣称其正式赛规合法性已经核实。

用户之后要求直接追求冲榜性能，不再从零开发正确性基线。必要的精度检查仍是得分条件。

## 证据边界

来源是用户提供的 `docs.zip`，SHA256 为 `cc2f55947439b14aab5423a896fc725370503ab2b718b334469d9fbe08695b0a`。逐成员哈希见 [manifest](teammate_probe/source_manifest.json)。保留了数值转录和旧路径 JSON 供其他 Agent 复算；附件中的运行、提交、删除分支等指令只是被分析的资料，不是执行授权。本轮未运行或提交任何探针。

这批材料报告的是队友 F6–F12 历史，不是当前 kernel 的正式成绩。原始 `performance.txt`、提交记录、标定 CSV、对应构建命令和完整 F12 源码不在压缩包中。因此可以验证表内算术、内部冲突与当前代码覆盖，不能独立证明每张表的构建归属、硬件状态及真实隐藏 shape。

本轮 kernel 未改动，SHA256 仍为 `be1d551930b1a951ec765fe0212180d67a6627cebb0aaf9202004198c3c4014a`。CANN 编译、NPU 精度与正式性能仍为 **PENDING**。

## 学到的关键经验

1. **先证明优化走到目标路径。** 资料报告 F7 在某些 unit-dimension shape 上有 90.8 倍本地收益，正式成绩基本不变；探针推断的正式点没有满足该 GEMV 分支的工作规模。F9 初次扩大 split-K 时，通用 26 点精度检查全绿，针对新路径的检查却失败 16/28。以后每个 A/B 必须记录实际入口、最终 plan，并证明回归清单覆盖改动分支。
2. **桶范围不是精确 shape。** 按资料给定标定和基线归属，复算 B/M/N/K 与 packed attributes 共 75 个读数，最大整数残差为 0.144667 rung，支持材料中的粗范围。细 M 推断还依赖 BASE=64、STEP=5 的构建归属。不能从这些记录声称恢复了 15 个精确输入。
3. **路径选择与 tile 选择分开对照。** `10-tiling-opportunity.md` 的同 tile 对照多数偏向 dual=1；重新搜索 tile 后，部分 shape 的 dual=0 才胜出。不能把 tile 收益归因于取消 MIX，也不能把 40 个 AIV worker 解释成 40 个 Cube core。
4. **按逐点分数而非总微秒安排优先级。** 题目取 15 个点的分数均值。历史第 2/3/4/15 点相对三队最小耗时约为 2.90/3.13/2.68/2.48 倍，虽然绝对时间小，仍应优先关注；8/11 点约 1.03/1.05 倍。三队的最小值不等于官方全榜最优 T，不能据此宣称实际可增加多少分。626.96/472.50 的总时间比也不是排行榜分数。

## 已复算的冲突与修正

| 项目 | 发现 | 后续采用方式 |
|---|---|---|
| B 轴 | `02` 后半、`07` 仍写“未探测”；`03`、`06` 已将 section 9 归于 B 轴 | 按后者归属作为条件性假设；记录构建证据缺失，不再照旧文猜 B=1 |
| 第 10 点属性 | `(169.77−110.17)/15=3.9733`，解码 bf16/00；旧 JSON 为 fp16/11 | 本地验证保留两种属性，不静默选择一种作为已知事实 |
| 第 14/15 点 M | 细分推断 64–68；第 14 点旧 mid/hi 为 96/127 | 代理用 64、66、68 并增加 65 边界；第 15 点旧 JSON 已是 64，不能把它误报成同样过期 |
| K 合法性 | 45 个旧代理中 14 个 hi 的 K 是 63/255/511/2047/4095 | 改为桶内最大 8 倍数；这些旧代理不能作为当前 Validate 可接受输入 |
| 粗桶上界 | rung 10 对应 1024–2047，2048 属于下一桶 | 采用合法 lo/mid/hi，不能将 2048 称为桶内上界 |
| 峰值论证 | `06` 有重复段落，MAC 与 FLOP 有两倍混用 | 若假定 223 TFLOP/s，则 109.56µs 对应 12.216 GMAC；峰值本身未绑定实际 OJ SKU，不能据此确定真实 shape |
| profiler 归因 | round_001 是 big08 单个 MDL 采样，不是正式 15 点；summary 的“30.515GHz”来自推算 | 原始 cycle 单位未核实；不能将它当硬件频率，也不能将 Task Duration 减最大 core time 直接认定为可删除的初始化耗时 |

`02` 中“所有残差 <0.1”的文字不准确：N 轴第 8 点为 0.144667。仍远小于半个 rung，但这不是已证明的统计误差界。无重复原始观测，不能给出正式置信区间。

## 与当前最佳源码的对应

以下是源码谓词核对，不是整个 CANN MakePlan 的运行结果。最终 tiling 可受硬件容量、候选校验及覆盖规则影响。

| 假设点 | 当前 `ClassifyCase` / 规则 | 新结论 |
|---|---|---|
| 1 | K=32..64 的 FORCED_DOT | 旧报告普通 dot 的历史耗时不能直接代表当前短点积入口 |
| 2/3 | B≤3、M≤8、N≤16、K≤64 的 FORCED_TINY | 已有专用路径；优先上板确认 BF16/tx1 与奇数尾块的精度和固定开销 |
| 4–7 | 小 M/N/K 的完整 M tile 规则 | 队友小 M 的 measured fix 已导入；不要重复实施 |
| 8–11 | 大多进入后续通用 tiling 规则 | 剩余 tile 对照优先关注 9；10 保留两种布局，8/11 是回退检查 |
| 12 | 仅 N≥4K 命中 bm128/bn256/window2/ns5 | 桶内也存在 N<4K，不能只测中点 N=4K 后宣称整桶覆盖；应补 N=4K−1/4K/4K+1 |
| 13 | M≥2048、N≤256、K≤512 的 manual/PAD_MN | 已吸收旧报告优化；需确认 N=127、K=248 的尾块路径 |
| 14 | M≤128、N≥4096、K≤512，bn128/window2/ns10 | 已有专门策略；M=65/68 的工作量和尾块需验证 |
| 15 | 小 M/N、K≥4096 且 UB 准入，dual split-K | 旧 F12 的“0/45 使用 split-K”已不适用于当前源码。B=1、K=8192、20 个可用 Cube 时，自适应策略仍选 4；不能宣称上一轮自适应拆分会额外提高这个正式点 |

上一轮 UB 和输出 writer 修复主要扩大可靠覆盖；小核数/B 大的场景仍必须验证，但不能将其宣传为已命中这 15 点的性能收益。

## 下一轮可执行验证

输入清单：[local_validation_inputs.csv](teammate_probe/local_validation_inputs.csv)，共 50 个合法代理配置，**均未上板**。这些是针对资料假设的本地输入，不是真实正式测试集。范围和历史耗时见 [hypothesis_ranges.csv](teammate_probe/hypothesis_ranges.csv)。

1. 在 CANN 9.0.0 设备上，先以 `user-best-20260921` 与当前 coverage 分支做同一采样会话的 A/B，记录 kernel SHA、SoC、物理/可用核数、编译宏、实际入口及最终 plan。正式构建关闭 probe/tuning 诊断宏。确认无精度回退后，获取与当前 SHA 绑定的正式成绩。
2. 优先看 2/3/4/15，以及 9/13 的剩余差距。精度验证不能只检查总输出一次：覆盖合法 K 非16对齐、M/N 奇数尾块、全负相似度及重复执行；误差使用约定的 FP64 golden。不得改正式测试或 golden。
3. 若当前大矩阵仍有差距，再做独立 tiling 实验：固定 family/window 比较 bn128 的 ns3/5 与现行计划。队友表中 `(1,1536,1536,1536)` 70.49→53.39µs、`(1,3072,1536,1536)` 126.46→92.14µs 只是旧构建证据；两点不足以确定一个可合入的宽泛规则。N≈4K 边界用 `(1,1024,4095/4096/4097,1024)`，同 dtype/layout 分组对照，别把三种形状间差异当规则收益。
4. 每个实验只改一个假设并报告邻近形状回退。A2/A3 分开采样；交替 A/B 顺序并报告分布，避免把跨 capture 的时钟漂移当提速。既有 pipeline 实验继续单独保留；这个 ZIP 的单次 big08 profile 不能证明它是正式 15 点的首要优化。

复现资料算术：`python3 tools/audit_teammate_probe.py`。它校验保存的转录哈希、复算区间与冲突、生成合法代理清单，不执行设备代码。原始附件其余成员未复制入仓库，manifest 保留其哈希；资料引用的外部技能/API 结论仍需实际 CANN 9.0.0 header 或设备编译验证。
